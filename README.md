### 📂 Задания и реализация

#### Задание 1: Шаблонный репозиторий `Repository<T>`
- **Условие:** Реализовать инфраструктурный класс `Repository<T>`, который хранит объекты любого типа и предоставляет методы для работы с ними, включая работу с предикатами и компараторами.
- **Код:** [Lab5Task1](./Lab5Task1.cpp)
- **Ключевые особенности:**
  - **Параметризация типа:** Один класс работает с `int`, `std::string` и `Animal*` без дублирования кода
  - **Работа с предикатами:** Метод `findFirst()` принимает `std::function<bool(const T&)>` — лямбду или указатель на функцию
  - **Фильтрация:** Метод `filter()` возвращает новый `Repository<T>` с отобранными элементами
  - **Сортировка:** Метод `sortBy()` принимает компаратор и использует `std::sort`
  - **Обработка ошибок:** Выбрасывание `std::out_of_range` и `std::runtime_error` при некорректных индексах или отсутствии результатов

#### Задание 2: Шаблонные алгоритмы (функциональный стиль)
- **Условие:** Реализовать набор шаблонных функций для обработки коллекций: `findAll`, `countIf`, `transformAll`, `groupBy`, `reduce`. Использовать алгоритмы STL.
- **Код:** [Lab5Task2](./Lab5Task2.cpp)
- **Ключевые особенности:**
  - **`findAll`** — возвращает вектор элементов, удовлетворяющих условию (на базе `std::copy_if`)
  - **`countIf`** — подсчет элементов по предикату (аналог `std::count_if`)
  - **`transformAll`** — преобразование каждого элемента через функцию (на базе `std::transform`)
  - **`groupBy`** — группировка по ключу с использованием `std::map<Key, vector<T>>`
  - **`reduce`** — свертка коллекции в одно значение (на базе `std::accumulate`)
  - **Демонстрация гибкости:** Один и тот же `findAll` ищет четные числа, слова на букву 'A' и животных тяжелее 100 кг

#### Задание 3: Собственный шаблонный контейнер `DynamicArray<T>`
- **Условие:** Разработать собственный одномерный динамический массив с возможностью расширения, обработкой ошибок и демонстрацией работы с разными типами.
- **Код:** [Lab5Task3](./Lab5Task3.cpp)
- **Ключевые особенности:**
  - **Автоматическое расширение:** При заполнении емкость удваивается (`capacity *= 2`), как в `std::vector`
  - **Rule of Three:** Реализованы конструктор копирования, оператор присваивания и деструктор для корректного управления памятью
  - **Перегрузка операторов:** `operator[]` с константной и неконстантной версиями
  - **Жесткий лимит:** Параметр `max_capacity` защищает от бесконечного роста памяти
  - **Полный набор исключений:**
    - `std::overflow_error` — при достижении максимального предела
    - `std::underflow_error` — при извлечении из пустого массива
    - `std::out_of_range` — при выходе за границы

### 🔗 Связь шаблонов и полиморфизма (Ключевой инсайт)

В этой лабораторной работе я на практике увидел разницу между двумя механизмами обобщения в C++:

| Аспект | Полиморфизм (Lab 3-4) | Шаблоны (Lab 5) |
|--------|----------------------|-----------------|
| **Когда определяется тип** | Во время выполнения (runtime) | Во время компиляции (compile-time) |
| **Механизм** | Виртуальные функции, указатели на базовый класс | Генерация кода компилятором для каждого типа |
| **Производительность** | Небольшой оверхед на vtable | Нулевой оверхед — код инлайнится |
| **Применение** | Разные объекты с общим интерфейсом (`Animal*`) | Один алгоритм для разных типов (`int`, `string`, `Animal*`) |
| **Пример из лабы** | `Repository<Animal*>` хранит львов, слонов, пингвинов | `Repository<int>`, `Repository<string>`, `Repository<Animal*>` — один класс, три типа |

**Вывод:** Шаблоны и полиморфизм не конкурируют, а **дополняют друг друга**. В `Repository<Animal*>` они работают вместе: шаблон дает универсальный контейнер, а полиморфизм позволяет хранить в нем разнородные объекты.

### 💡 Выводы и инсайты

В ходе выполнения лабораторной работы:

1. **Понял философию STL:** Алгоритмы STL не знают о типах данных — они работают через итераторы и функторы. Это делает их бесконечно переиспользуемыми. Мой `DynamicArray` следует той же философии.

2. **Оценил мощь лямбд:** Передача условий как `[](int n) { return n % 2 == 0; }` делает код декларативным — мы описываем *что* хотим получить, а не *как* это сделать.

3. **Разобрался с Rule of Three на практике:** При реализации `DynamicArray` я столкнулся с проблемой поверхностного копирования — два объекта указывали на один и тот же массив. Реализация конструктора копирования и оператора присваивания решила эту проблему.

4. **Увидел связь с реальными библиотеками:** Мой `DynamicArray` — это упрощенный аналог `std::vector`, а `Repository<T>` напоминает `std::vector` + алгоритмы из `<algorithm>`. Понимание того, как это работает изнутри, делает использование STL осознанным.

5. **Освоил обработку граничных случаев:** Пустые коллекции, выход за границы, переполнение — все эти ситуации теперь обрабатываются через исключения, а не через возврат магических значений.
